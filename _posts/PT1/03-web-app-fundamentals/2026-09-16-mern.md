Il fingerprinting dello stack non è un'abilità accessoria: è un **moltiplicatore diretto della velocità di sfruttamento**. Una volta noti stack e versione, si conosce già una superficie di attacco plausibile.

Il flusso di lavoro dei red teamer esperti segue tre fasi:

1. **Identificazione dello stack** tramite segnali nella risposta HTTP
2. **Ricerca di una vulnerabilità applicabile**
3. **Esecuzione della catena di exploit**

Questa nota copre le prime due fasi (fingerprinting) e un caso concreto di fase 3: la **prototype pollution** su un'app MERN.


## Lo stack MERN

**MERN** è un acronimo che indica un insieme di tecnologie JavaScript usate per sviluppare applicazioni web full-stack:

-   **M** — **MongoDB**: database NoSQL document-oriented (dati in formato JSON)
-   **E** — **Express.js**: framework leggero per costruire server e API REST su Node.js
-   **R** — **React**: libreria frontend per costruire interfacce utente (lato browser)
-   **N** — **Node.js**: runtime JavaScript lato server

L'idea alla base è che si usa **un solo linguaggio — JavaScript — su tutto lo stack**, dal database al browser. Questo semplifica lo sviluppo perché non serve switchare tra linguaggi diversi per frontend e backend. La configurazione di base per MERN è la seguente:

``` Internet → :80/:443 (Nginx) → :3000/:5000 (Express) → :27017 (MongoDB)  ```

> In una configurazione corretta, Express e MongoDB sono accessibili sono da localhost, Nginx fa da intermediario e la porta di Express non è raggiungibile dall'esterno.

## Fingerprinting MERN

Anche quando vediamo solo Nginx, ci sono segnali che suggeriscono un backend Node/Express:

Segnale |  Esempio | Affidabilità
---|---|---|
Header `X-Powered-By` | `X-Powered-By: Express` | Media (spesso disabilitato) |
Errori 502/503 con body JSON |`{"error": "..."}` |Media |
Route tipiche |`/api/v1/`, `/auth/login` | Bassa (dipende dall'app) |
Response time pattern |caratteristici di Node.js | Bassa |
Cookie `connect.sid` |`Set-Cookie: connect.sid=...` |Alta (se presente) |
404 di default |`Cannot GET /nonexistent` |Alta (se non custom) |

## Exploiting MERN
Il passo successivo al fingerprinting è l'enumerazione della superficie API. Le applicazioni MERN espongono comunemente API JSON per aggiornamenti del profilo, preferenze e impostazioni utente.
