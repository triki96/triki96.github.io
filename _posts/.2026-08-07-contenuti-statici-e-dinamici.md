## La domanda

So che PHP è un linguaggio di backend, ma non capivo bene perché un file `.php` finisse dentro un URL. Approfondendo, il dubbio più grande era: qual è davvero la differenza tra un contenuto "statico" e uno "dinamico" in una pagina web?

## La risposta

### Contenuto statico

È un file che esiste già, pronto e identico, sul server. Il server lo legge dal disco e lo invia così com'è, senza nessuna elaborazione. Se lo richiedi cento volte, ricevi sempre esattamente lo stesso file.

Esempi tipici: file `.html` scritti a mano, `.css`, `.js`, immagini, video, PDF.

```
Richiesta → il server legge style.css dal disco → lo invia identico
```

### Contenuto dinamico

Non esiste come file pronto: viene **generato al momento**, ogni volta che arriva una richiesta, eseguendo del codice lato server (PHP, Python, Node.js, ecc.) che magari interroga un database, controlla chi sei loggato, legge parametri dalla query string, e costruisce l'HTML su misura per quella specifica richiesta.

```
Richiesta → il server esegue index.php → query al database → genera HTML diverso ogni volta
```

### Esempio pratico

Un sito e-commerce rende bene l'idea:

- **Statico**: il logo dell'azienda, il CSS del layout, le icone → sempre identici per tutti
- **Dinamico**: la pagina "Il mio carrello" → contenuto completamente diverso da utente a utente, e diverso ogni volta che aggiungi o rimuovi un prodotto

Un URL come `index.php?name=adam` è un classico esempio di contenuto dinamico: lo stesso URL, con parametri diversi, produce output diverso, generato al volo dall'interprete PHP sul server. Il browser non riceve mai il codice PHP, solo l'HTML risultante.

> Il codice sorgente `.php` non lascia mai il server. Il client riceve solo l'output generato (di solito HTML).
{: .prompt-tip }

### La zona grigia: approcci ibridi

Molti siti moderni non sono puramente statici o dinamici:

- **Static Site Generation (SSG)**: il contenuto è "dinamico" nel senso che viene generato da codice/database, ma **pre-generato una volta** al momento della pubblicazione, poi servito come file statico a tutti. Questo stesso blog Jekyll ne è un esempio.
- **Server-Side Rendering (SSR)**: generato dinamicamente a ogni richiesta, ma direttamente in HTML già pronto, invece di costruirlo via JavaScript nel browser.

## Rilevanza pentest

Questa distinzione conta molto in fase di reconnaissance: il contenuto dinamico è dove si concentra quasi tutta la superficie d'attacco interessante (SQL injection, XSS, command injection, logica di business sfruttabile), perché è lì che il server **elabora input controllato dall'utente**.

Un file statico, essendo semplicemente letto e inviato senza elaborazione, ha una superficie d'attacco molto più ridotta — al massimo path traversal, se la configurazione del server è sbagliata.

Vedere un URL con `.php`, `.asp`, o parametri in query string (`?id=1`) è quindi un segnale utile durante un assessment: indica un punto dove il server sta processando ed è quindi un candidato prioritario per i test di injection.
